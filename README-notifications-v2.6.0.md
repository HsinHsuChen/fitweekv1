# FitWeek v2.6.0｜訓練提醒

這份更新包含完整網站、原有 15 張動作圖片，以及可獨立部署的推播服務。課表、啞鈴重量、節拍器、飲食照片與既有訓練紀錄格式不變。

## 更新網站

1. 解壓縮後，將根目錄的網站檔案與 `images` 資料夾上傳至原 GitHub Pages 專案，覆蓋同名檔案。不要上傳 ZIP 本身，也不要多包一層資料夾。
2. 關閉舊網頁，再開啟並確認頁面顯示 v2.6.0。不要清除網站資料；原紀錄仍在本機。
3. 在設定中的「iPhone 桌面小工具」重新複製新版 `FitWeek-Streak` 程式，替換 Scriptable 原程式，再按一次「同步到桌面小工具」。

**完成上述步驟，網頁提醒卡就能使用。只有上傳 GitHub 不會自動開始鎖定畫面推播。**

## 提醒規則

- 台灣時間每日 03:00 換日，沿用既有連勝演算法。
- 至少一組有效次數，並按完成儲存後才算運動紀錄；草稿、只開始計時、飲食紀錄都不算。
- 同一筆重複儲存不增加次數；同一訓練日兩筆不同有效紀錄都會累計。
- 依訓練起始時間歸屬區間。02:50 開始、03:20 儲存的紀錄仍算前一訓練日，不會同時讓兩個區間都完成。
- 本區間沒有有效紀錄：網頁顯示提醒卡。有紀錄：隱藏提醒卡，並嘗試關閉本網站同一標籤的通知。
- 週日 03:00 到週一 03:00 是休息區間，不催促訓練。
- 網頁與新版 Scriptable 共用五種配色、激勵語，依訓練日選色；不再各自隨機。因 iOS 小工具更新時機不固定，跨日可能短暫不同色。
- Scriptable 小工具的次數仍需手動同步；這次沒有宣稱已加入自動背景同步。
- 一般 iPhone 通知只用色彩符號、文字呼應小工具，無法控制整張底色，也不保證常駐。

## 部署推播服務（需要一次設定）

需要一台能長時間執行 Node.js 22.9 以上版本、支援 HTTPS 且提供持久磁碟的主機。這是額外服務，GitHub Pages 無法執行。主機需允許連線至 Apple／Google／Mozilla 推播端點。使用單一服務實例，不要讓多台實例同時寫同一份 JSON 資料庫。

### Node.js 方式

將整個專案放在主機上，保留根目錄的 `streak.js`、`streak-themes.js` 與 `push-server` 的相對位置。在 `push-server` 執行：

```sh
npm ci --omit=dev --ignore-scripts
npm run keys
```

這會在該主機建立 `.env`。編輯其中兩項：

- `SITE_URL`：目前訓練網站的根網址，必須包含 GitHub 專案路徑並以 `/` 結尾。例如 `https://你的帳號.github.io/你的專案/`。
- `VAPID_SUBJECT`：你的聯絡信箱，例如 `mailto:你的信箱`。

保留自動產生的 `PAIRING_CODE`、`VAPID_PUBLIC_KEY` 與 `VAPID_PRIVATE_KEY`。設定 `DATA_DIR` 指向持久磁碟，再執行：

```sh
npm start
```

以主機的 HTTPS 反向代理對外提供服務，內部預設連接埠為 3000。可開啟 `https://你的提醒服務/health`，應看到 `{"ok":true}`。服務不會供應網站內容；原網站繼續由 GitHub Pages 提供。

### Docker 方式

可從專案根目錄建置 `push-server/Dockerfile`，建置內容需包含上述兩個共用檔案。啟動時提供 `.env` 中的環境變數並將持久磁碟掛載到 `/data`。容器不自動產生正式金鑰，以免重啟後換金鑰造成原訂閱失效。

**不要把真正的 `.env`、私鑰、配對碼或 `data/devices.json` 上傳到 GitHub Pages。** 更新包只有範例，沒有正式金鑰或個人訂閱。

## 在 iPhone 啟用

1. Safari 開啟原網站 → 分享 → 加入主畫面。
2. 從主畫面開啟 FitWeek → 設定 → 訓練提醒與鎖定畫面通知。
3. 設定每天提醒時間，預設台灣時間 19:30。
4. 展開「連接推播服務」，填入剛部署的 HTTPS 服務網址，以及主機 `.env` 中的配對碼。
5. 先按「確認服務連線」，再按「允許並啟用通知」，同意系統權限。
6. 按「發送測試通知」。測試通知會標示測試，即使今天已運動也會發送，方便驗證。

完成後，每個非休息訓練日到指定時間、且服務尚未收到該區間的完成紀錄，才發送一則提醒。同一區間不會因重新整理或重新儲存而重複發送。

## 同步、停用與失效處理

- 網頁只傳送有效訓練的起始時間、日期、去重鍵與提醒時間。完整訓練內容、重量、餐點照片與飲食不會上傳。
- 開啟網頁、完成／修改紀錄、還原備份、恢復連線時同步提醒狀態；傳輸失敗會在設定頁顯示，不會把本機訓練儲存判成失敗。
- 離線完成後，系統無法立刻通知遠端服務；連線並開啟網頁後才能停止後續催促。
- 推播短暫延遲、剛好在儲存前已送出時，仍可能抵達。若本機已完成，通知改顯示完成訊息，不以靜默推播假裝即時動態。
- 通知投遞、專注模式、保留時間與小工具刷新由 iOS 決定，無法保證立即或常駐。
- 在設定按「停用通知」會先撤銷服務端訂閱，再取消瀏覽器訂閱。清除本機紀錄前也會先停用，以免清完仍收到舊提醒。
- 通知配對憑證不在訓練 JSON 備份內；換手機或重裝後需重新配對。
- 推播服務每 30 秒檢查，發送時間容許 10 分鐘誤差；過了時段不補發大量舊提醒。無效訂閱回應 404／410 時移除。
- 推播服務儲存檔含訂閱資訊，請使用持久磁碟並限制存取，維持同一組 VAPID 金鑰。
