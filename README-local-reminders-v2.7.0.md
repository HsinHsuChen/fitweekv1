# FitWeek v2.7.0｜手機本機提醒

改用你手機上的 Scriptable 預約通知，不需要部署伺服器、不需要 Render、不需要 VAPID 金鑰。網頁繼續放在原本的 GitHub Pages。原課表、連勝規則、15 張圖片、節拍器、訓練與飲食資料格式不變。

## 第一次使用

1. 解壓縮完整更新包，將內容上傳到原 GitHub 專案，覆蓋同名檔，保留 `images/exercises` 資料夾。不要上傳 ZIP 本身，不要清除手機網站資料。
2. 關閉舊網頁並重新開啟，在設定確認版本為 v2.7.0。
3. 進入「設定 → iPhone 桌面小工具」，按「複製小工具程式」。到 Scriptable 開啟原本的 `FitWeek-Streak`，選取全部舊程式並替換。名稱維持 `FitWeek-Streak`。
4. 回到網站，展開「手機本機提醒（不需伺服器）」，勾選啟用並選時間，預設台灣時間 19:30。
5. 按「儲存並同步提醒」。Scriptable 第一次要求通知權限時選允許。查看 Scriptable 的確認畫面，會列出已提交幾則排程與涵蓋期限。
6. 可回網站按「測試通知（10 秒後）」，再同步開啟 Scriptable。關閉預覽或回到主畫面，等待測試通知。

若沒有看到通知，在 iPhone「設定 → 通知 → Scriptable」確認允許通知、鎖定畫面與通知中心；專注模式／通知摘要也會影響顯示。

## 每次完成運動

先在網站按「完成並儲存訓練」，再按「同步小工具與提醒」。這會更新連勝、取消該訓練日待發送的提醒、移除本站已顯示的本機通知，並重新補足七個訓練日區間的排程。

**只儲存網頁不會自動把資料送給 Scriptable。** 網頁與 Scriptable 是不同程式，因此需要按一次同步。網頁只顯示上次「開啟同步要求」時間，不會假裝已確認手機排程成功。請以 Scriptable 確認畫面為準。

## 規則

- 每個台灣時間 03:00 起的訓練日區間，最多一則一般提醒。
- 每次同步安排目前及接續六個訓練日區間，跳過週日，通常是五到六則。已過去的提醒不補發。
- 週日 03:00 至週一 03:00 不提醒。若設定凌晨 00:30，依 03:00 換日規則屬於前一訓練日。
- 至少一組有效次數且完成儲存，才算有效訓練；草稿與飲食紀錄不算。
- 同一筆重複儲存只計一次，同區間不同訓練照常累計。
- 02:50 開始、03:20 儲存仍歸前一區間；同步不會將兩個區間同時計為完成。
- 連勝與提醒文字依上次同步資料推算；未來若沒有新紀錄，顯示次數會按原規則歸零，不會永遠保留舊連勝。
- 網頁、小工具與預約通知共用依訓練日選出的配色、激勵語。一般通知僅用色彩符號呼應，不會變更 iOS 整張通知底色。
- 小工具背景刷新只顯示資料，不會重排通知或跳出權限視窗。
- 連續七個訓練日未同步，排程會用完；再次同步即可補足。這是七日滾動排程，不是無限自動排程。
- 系統收到排程後不必一直開著 Scriptable 或網頁；通知來源顯示 Scriptable。iOS 決定最終顯示時間與保留方式，無法保證常駐。
- 只針對本站 FitWeek 通知識別碼更新／移除，不呼叫 Scriptable 的「清除全部通知」。測試通知不會增加訓練次數。

## 停用

在網站設定按「停用並同步」，到 Scriptable 確認取消結果。只取消勾選但沒有同步，不會刪除手機已排程的通知。

若要清除網頁所有資料，請先停用並同步。網頁本機資料與 Scriptable 排程分開，刪除網站資料不會自動刪除 Scriptable 通知。

## 從 v2.6 遷移

如果曾成功連接遠端推播服務，設定頁會顯示「偵測到舊遠端推播設定」。先按「停用舊遠端推播」，再使用本機同步，避免兩套通知重複。程式不會自動連線或上傳新訓練至舊服務。

如果原主機已無法連線，先在主機平台確認舊服務已刪除／停止，再按「已刪除主機，移除舊連線」。需要協助時請回報畫面，不要貼金鑰。不再使用付費主機時，另至平台刪除服務及磁碟，才能停止相關計費。

更新包保留 v2.6 的 `push-server` 與舊說明供回溯；本版本不需要使用它們，請依本份說明操作。
